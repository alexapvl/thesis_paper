\chapter{Introduction}

\label{intro}

Music performances are not experienced through sound alone. In live concerts, club environments, and electronic music events, lighting plays a central role in shaping atmosphere, directing attention, and amplifying emotional intensity. Changes in colour, brightness, movement, and timing can make a musical moment feel larger, more intimate, more aggressive, or more immersive. For electronic music in particular, where repetition, gradual build-ups, drops, and timbral changes are essential expressive devices, visual response becomes part of the perceived structure of the performance.

At the same time, expressive stage lighting is difficult to automate. Traditional lighting design depends on human expertise, preparation time, and detailed manual programming. Automatic Stage Lighting Control addresses this problem by generating lighting parameters from music, with the potential to support live performances, influence the audience's emotional experience, and provide a more accessible alternative to dedicated lighting engineers. However, many prior approaches rely on a two-stage strategy: first classifying music into predefined style or emotion categories, then assigning lighting patterns to those categories. Such pipelines can be useful, but they also reduce the richness of music to a limited set of labels before the visual output is generated.

Recent generative approaches suggest a more flexible direction. Instead of mapping a classified category to a fixed lighting rule, Skip-BART treats automatic stage lighting as a sequence generation problem and learns to produce lighting sequences directly from music. This framing is especially relevant for creative applications because lighting design is not only a technical control problem, but also an artistic process involving timing, continuity, contrast, and expressive variation. A system that can use such models in real time must therefore solve more than an inference problem. It must capture or play audio, extract and stream meaningful signals, run analysis and generative models, transport outputs with low overhead, and update an interactive visual scene quickly enough for the result to feel synchronized with the music.

The motivation for this thesis comes from a personal intersection between two long-standing interests: programming and electronic music. Programming provides the tools for building systems, structuring complex processes, and turning abstract ideas into working applications. Electronic music provides a creative context where rhythm, timbre, energy, and atmosphere are central, and where the connection between sound and light is immediately perceptible. This thesis explores that intersection by asking how music analysis and generative lighting models can be integrated into an application that is not only technically functional, but also visually engaging and suitable for interactive demonstration.

The objective of the thesis is to design and implement a real-time sound-to-light prototype for generative stage lighting. The system analyzes audio while it is playing, extracts information relevant to musical timing and visual control, and uses model outputs to update a virtual stage environment. The application follows a hybrid architecture: the browser handles audio input, playback, user interface, shared frontend state, and Three.js rendering, while a local Python server runs beat tracking and Skip-BART inference in their native PyTorch environment. Raw PCM audio chunks are sent upstream from the browser to the server, and beat, tempo, hue, and value parameters are sent downstream to drive state updates and scene rendering.

A central design concern is real-time responsiveness. In this project, the system does not need to satisfy the extremely strict action-to-sound constraints of a musical instrument, but it must still keep visual changes close enough to musical events to be perceived as synchronized. The latency budget includes audio capture and buffering, feature extraction, model inference, message transport, and rendering. For this reason, the thesis treats system design as the management of latency, modularity, and usability under the constraints of the chosen platform. The resulting architecture targets a sub-100 ms end-to-end synchronization threshold and estimates the full pipeline at approximately 90 ms, leaving the system within the intended synchronous perception zone.

The personal contribution of this work is the application-level integration of multiple components that usually belong to separate domains. MIR and deep-learning models provide the analytical and generative intelligence; the Web Audio API provides real-time audio capture, playback, analysis, and streaming support; FastAPI and WebSockets connect the browser runtime to the Python model stack; React, Zustand, React Three Fiber, and Three.js provide the interface, shared state, and 3D visual environment. The thesis contribution is therefore not limited to using existing models, but consists in designing the architecture, data flow, interaction layer, and rendering pipeline that make those models usable in a coherent real-time stage-lighting application.

This integration also defines the originality of the work. The project does not claim to introduce a new beat tracker or a new generative lighting model. Instead, it contributes a practical bridge between research models and a working creative system. The prototype supports both microphone and file-based audio sources as first-class inputs and normalizes them into the same real-time processing path. It exposes playback, monitoring, lighting, and scene controls so the system can be operated, inspected, and adjusted during a thesis demonstration. It also separates responsibilities between browser-side interaction and rendering and server-side inference, preserving accessibility while avoiding the memory, conversion, and performance limitations of full browser-side model deployment.

The thesis is organized as follows. Chapter~\ref{chap:theoretical-background} introduces the theoretical foundations of the work, beginning with digital audio and MIR, then moving through rhythmic structure, beat tracking, music-visual mapping, automated stage lighting control, real-time processing, and the deep-learning architectures relevant to the system. Chapter~\ref{chap:technologies-and-platform-constraints} discusses technology selection and platform constraints, focusing on the web platform, 3D rendering with WebGL and Three.js, audio processing through the Web Audio API, machine-learning deployment options, communication mechanisms, frontend framework selection, and the design implications of browser constraints. Chapter~\ref{chap:methodology-requirements-system-design} translates those constraints into methodology, requirements, architectural decisions, module responsibilities, frontend data flow, and the end-to-end runtime pipeline. Chapter~\ref{conclusions} concludes the thesis by consolidating the outcomes of the prototype and identifying the main lessons, limitations, and possible directions for future development.

By combining music analysis, generative lighting control, real-time systems engineering, and interactive visual rendering, this thesis demonstrates how computational methods can support creative performance technologies. The resulting prototype shows that the connection between sound and light can be treated not only as a visualization problem, but as a real-time interactive system design problem in which artistic intention, model behavior, latency constraints, and user control must be considered together.
